# MiniMax H3 — the facts this plan relies on, and the gotchas

The long-form evaluation is
[`../../docs/documents/research/MiniMax_H3_Evaluation.md`](../../docs/documents/research/MiniMax_H3_Evaluation.md)
(cited as **Eval §n**). This file keeps only what the plan depends on. Labels: **V** = read in code,
config, weight header or primary doc; **R** = reported by someone, not reproduced; **I** = our
inference. Nothing here has been run. **V (code)** marks facts read on 2026-10-12 in
DiffSynth-Studio at the pinned commit `acf2ad2` (`expv2_common.DIFFSYNTH_SHA`); the file named
is the evidence.

## 1. Facts

| | Value | Label, source |
|---|---|---|

| Build used here | `Comfy-Org/MiniMax-H3: diffusion_models/minimax_h3_fl2va_pruned_bf16.safetensors`, 40.2 GB. The AdaLN MLP is replaced by a timestep lookup table | V file name and size; R behaviour, Eval §1 |
| Text encoder | Qwen3-VL-32B (layer 50 hidden states), 66.7 GB bf16. The **start frame also goes through it** as vision tokens | V, Eval §1 |
| Video VAE | f16t4d24, causal conv encoder + 36-layer ViT decoder, 2.6B params fp32. 17-frame chunks → 5 latents | V, Eval §1 |
| Tokens | patch 1×2×2 → one token per 32×32 px. 768² = 576 tokens per latent frame | V |
| Frame grid | 17n+5 frames → 5n+2 latents: **22 → 7, 39 → 12, 56 → 17** | V, DiffSynth doc |
| First-frame conditioning | keyframe VAE-encoded into extra rows held at t = 0.999 with frame-0 RoPE; the generated frame 0 is **not** overwritten | V (diffusers code, agent read), Eval §1 |
| Guidance | CFG-distilled: one forward per step; DiffSynth defaults `cfg_scale` 1.0 and `negative_prompt` `" "` and says the negative "takes no effect" | V, DiffSynth doc l.98, l.105 |
| Inference schedule | `flow_shift` 12 (video), `audio_flow_shift` 3, two independent sigma schedules, 50 steps default | V, DiffSynth doc l.106–107 |
| Training (DiffSynth) | `examples/minimax_h3/model_training/train.py`; stage 1 `--task sft:data_process` loads Qwen3-VL + both VAEs and **no DiT** (the pruned example script), and writes one `.pth` per clip to `<output>/0/<i>.pth`; stage 2 `--task sft:train` loads the DiT only and finds `.pth` files **recursively** under `--dataset_base_path` (`UnifiedDataset.search_for_cached_data_files`), so buckets merge by sharing a parent directory. LoRA default targets `qkv_proj,out_proj`, rank 32 | V, DiffSynth doc l.229; V (code) `diffsynth/core/data/unified_dataset.py`, `diffusion/runner.py` |
| Training loss | per sample: one `timestep_id` uniform over the 1,000-entry training table, **shared by video and audio** (each indexes its own table); fresh `randn` noise; MSE on the velocity times a bell-shaped weight over σ | V (code) `diffsynth/diffusion/loss.py` `FlowMatchSFTMiniMaxH3AudioVideoLoss`, `flow_match.py` `set_training_weight` |

| Prompt (I2V) | `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.` then `integrated_multimodal_description: [Shot 1] …`, `overall_soundscape: …`, `non_diegetic_music: …` | V, model card I2V example |
| Output | 4–15 s officially, 24 fps, short edge 768 default, 32 kHz stereo audio on every call | V, Eval §1 |

## 2. Gotchas — each one would silently corrupt a first run

| # | Gotcha | Consequence if missed | What the plan does |
|---|---|---|---|
| 2.1 | **Only CFG-distilled weights exist.** Plain flow-matching LoRA training "regresses to its pre-distilled state": washed-out output, lost prompt adherence. Degradation is reported at 3k–5k steps even with countermeasures (Eval §6.1) | A run that looks fine on loss produces foggy, off-prompt clips | Guidance loss `--training_cfg_scale 4` in arm A; DeCFG adapter as pre-declared arm D; wash-out bar V11; short budget, early checkpoints |
| 2.2 | **Frame 0 is not pinned.** The output's first frame only approximates the supplied frame (Wan pins it by concatenation). In DiffSynth's `model_fn_minimax_h3` every target video row gets the same timestep; only the keyframe rows are held at `max(t, 0.999)` (t = 1 is clean there) — V (code) | "On-model" start frames drift, and every metric that uses frame 0 as reference is off | Bar V9 (first-frame fidelity); Tier 1 excludes the frame-0 latent; motion metrics reference the *supplied* frame |
| 2.3 | **The pipeline snaps `num_frames` up to the next 17n+5**, and retake pads a short source by repeating its last frame (V, DiffSynth doc l.101, l.134). The **training** loader does the opposite: a file shorter than `--num_frames` is snapped **down** to the next 17n+5 (22 → 5 frames), never padded (V (code) `FrameSamplerByRateMixin.get_num_frames`) | A file one frame short trains as a 5-frame clip, silently | Prep writes every clip with its exact length (+ the tail frame of 2.17) and asserts it; `prep/check_loader.py` and G0.2e replay the loader on every file |
| 2.4 | **The FL2VA training example trains first + last frame** (`input_image,end_image`). musubi's video FL2VA trains first + last only (Eval §6.2). In `train.py` `input_image` = `video[0]` at keyframe index 0 and `end_image` = `video[-1]` at index −1 — V (code) | Train/inference mismatch: the LoRA learns to expect an end anchor we never give | `--extra_inputs input_image` only; G0.2 dumps the conditioning rows in training and inference and asserts no end-frame rows |
| 2.5 | **DiffSynth trains at shift 2.22 for both modalities and infers at 12/3.** The maintainers chose 2.22 empirically because the training shift was not released (V, DiffSynth #1583). It is the default argument of `set_timesteps_minimax_h3`, and nothing passes another value (V (code) `flow_match.py`, `training_module.py` `switch_pipe_to_training_mode`) | An untested hyperparameter that changes which noise levels the LoRA learns | Two 122-step pilots: S12 (video 12 / audio 3, the inference pairing) vs S2.22 (2.22 / 2.22); Tier 1 decides (PLAN §6.3). `patches/diffsynth-h3-train-shift.patch` adds `--train_flow_shift` / `--train_audio_flow_shift` and prints the resulting σ quantiles at start-up |
| 2.6 | **The pruned build uses ComfyUI's QKV layout**, and LoRAs and adapters are layout-specific (V, example script comment). Pruned AdaLN is a lookup over discrete timesteps (R) | A LoRA trained on one build will not load, or loads wrongly, on the other; a lookup table can differ from the MLP between grid points | Train, evaluate and score on the **same pruned build**; G0.2 parity test against the full bf16 DiT at three t values |
| 2.7 | **The DiT and Qwen3-VL cannot be resident on one GPU together** (V, DiffSynth doc l.229). Every new start frame must pass through Qwen3-VL | Naive per-clip evaluation reloads 107 GB of weights per clip (C4) | Two-pass evaluation: encode every (caption, start frame) pair first, then load the DiT once per checkpoint. G0.2 checks the two-pass output equals the one-pass pipeline's |
| 2.8 | **The start frame enters twice:** Qwen3-VL vision tokens *and* DiT in-context latents. ai-toolkit may skip the text path in training (I, Eval §6.2). DiffSynth does both in training and inference: `MiniMaxH3Unit_PromptEmbedder` builds `<Picture 1>: <vision tokens>` + prompt via `presentation_fl2va`, and `MiniMaxH3Unit_KeyframeEncoder` builds the rows — V (code) | Train/inference mismatch on the identity signal | DiffSynth only; G0.2 asserts both paths are present in the stage-1 cache and at inference |
| 2.9 | **Audio is always generated and the audio stream is always forwarded.** Our clips are silent. The silent fallback only fires when the metadata row **has** an `input_audio` entry that fails to load (`parse_extra_inputs` reads `data["input_audio"]`, a missing column is a `KeyError`); it then trains on zeros of 800 × round(N/24 × 40) samples at 32 kHz — V (code) `train.py` | Missing audio inputs can crash stage 1, or a garbage audio target leaks into the loss | `input_audio` column = the clip's own mp4, which has no audio stream; `--silent_on_missing_audio`, `--audio_loss_weight 0`; G0.2d logs the audio loss term as exactly 0; audio stripped at export |
| 2.10 | **The prompt format is long, structured and "extremely sensitive"** (R). The Context-IR prompt rewriter that is "critical to the quality" is not released. Text tokens sit inside the DiT sequence | Our v8-style caption may be read as off-format; long captions cost sequence length | Official I2V line + three fields, our content in `integrated_multimodal_description`; one frozen template; ≤ 220 Qwen tokens asserted (PLAN §5.5) |
| 2.11 | **mp4 writers crush fine detail.** musubi found all its H3 writers at ~1 Mbps, "masquerading as generation artifacts" (V, musubi #1057) | The VAE gate and every Tier-2 metric would measure the encoder, not the model | All scoring reads PNG frames from memory or disk; mp4 only for viewing, CRF ≤ 16 |
| 2.12 | **Anime-style output is often animated on twos** (~12 fps effective; ~1 in 10 clips true 24 fps for the reporter, V, HF #74). The client's art is true 24 fps on ones (A2) | Clips look correct frame by frame but move at half rate | Cadence measured as the "twos index" against the source (G0.5), bar V10 |
| 2.13 | **H3's 2D output "leaned too heavily towards 3D"** (V, RunningHub LoRA card) | The v4 claymation basin again (~40% of Pax seeds there) | Manual rubric V2 checks shading; automated fill-flatness in V11; ≥ 3 seeds (B2) |
| 2.14 | **VAE reports against our art type:** line art fading (V, GitHub #73), colour shift on plain backgrounds (V, HF #78), fine background detail lost (V, DiffSynth #1585), brightness dips on a 17-frame cadence (V, #85, traced to a ComfyUI dtype bug, not the VAE) | Damage no LoRA can undo | G0.1 is a stop gate with a by-eye 4× check, a 2/255 ground-drift bar and a chunk-boundary brightness check |
| 2.15 | **DiffSynth has no LR scheduler flag and no optimizer-state resume.** `launch_training_task` always builds `torch.optim.lr_scheduler.ConstantLR(optimizer)` (whose defaults run the first 5 steps at LR/3), has no gradient clipping, and `--resume_from_checkpoint` loads model weights only (V (code) `runner.py`, `training_module.py`) | Constant LR at batch 1 gave mostly-noise updates on Wan (D4); stopping for gate breaks would lose the optimizer moments | `patches/diffsynth-cosine-lr.patch` (always applied) adds `--lr_scheduler cosine --lr_warmup_steps --lr_min_ratio` over optimizer steps and logs the LR to `loss.csv`; gate breaks are replaced by pilots + post-hoc checkpoint scoring (PLAN §6) |
| 2.16 | **What the guidance loss's unconditional branch drops** was undocumented. In code it drops **the text only**: the unconditional pass reuses every shared input (including the keyframe rows) and swaps in the negative prompt `" "`, which `presentation_fl2va` still prefixes with `<Picture 1>` vision tokens, so the start frame is in both branches (V (code) `loss.py`, `train.py` `get_pipeline_inputs`, `PromptEmbedder`). Sources disagree on stacking the DeCFG adapter with guidance loss (Eval §6.1) | Had it dropped the image too, the loss would sharpen the image condition along with the text | G0.2c confirms at runtime. The adapter and guidance loss are never stacked: arm A uses the loss, arm D the adapter |
| 2.17 | **The training loader reads the container duration to two decimals.** With `fix_frame_rate=True` the available length is `floor(duration × 24)`, and imageio's ffmpeg reader parses ffmpeg's `Duration: hh:mm:ss.xx`. 56 frames = 2.333 s prints as 2.33 → 55 frames → snapped down to **39** (2.3); a float duration can land at 21.999… the same way (V (code) `operators.py`; I for the imageio parse) | f56 clips train as 39 frames, silently | Every corpus mp4 carries **one extra copy of its last frame** (`expv2_common.LOADER_TAIL`). The loader still reads exactly `--num_frames`, so the tail is never trained; PNGs hold exactly N. `prep/check_loader.py` replays the loader on every file; G0.2e repeats it with DiffSynth's own `LoadVideo` |
| 2.18 | **`--save_steps` counts samples, not optimizer steps.** `ModelLogger.on_step_end` runs once per dataloader item, and checkpoints are named `step-<samples>` (V (code) `logger.py`) | `--save_steps 50` at accumulation 8 saves every 6.25 optimizer steps (≈ 80 checkpoints of the 504-step run) | `configs/train.sh` passes `--save_steps 400` (= 50 optimizer steps); every eval script maps `step-N` → optimizer step N/8 (`expv2_common.opt_step`) |
| 2.19 | **Stage 1 must also run with `--training_cfg_scale` > 1.** At 1.0 the data-process stage removes the negative prompt's embeddings from the cache (`force_remove_params_nega`), and stage 2's guidance loss then raises "requires unconditional inputs" (V (code) `train.py`, `loss.py`) | The main run dies at step 1 after hours of caching, or a re-cache is needed | `configs/cache.sh` passes `--training_cfg_scale 4`. One cache serves arm A and arm D (cfg 1 ignores the extra embeddings) |
| 2.20 | **No seed flag.** Timestep and noise sampling use torch's global RNG, unseeded; the `"seed": 42` in `get_pipeline_inputs` only seeds the cached initial noise (V (code) `train.py`) | Runs are not reproducible, and the two pilots differ by more than their shift | `patches/diffsynth-h3-train-shift.patch` adds `--seed` (`accelerate.utils.set_seed`); `train.sh` passes 42 |
| 2.21 | **Stage 2 still validates `--num_frames`** (17n+5) even though it reads a cache, and stage 1 loads Qwen3-VL (66.7 GB) and the video VAE onto **one** GPU together (V (code) `train.py`, `runner.py`; I that this is tight on 80 GB) | A stage-2 launch without `--num_frames` exits at argparse (default 81); stage 1 may OOM | `train.sh` passes `--num_frames 22` (unused). `CACHE_OFFLOAD=1 configs/cache.sh` adds `--enable_model_cpu_offload` if stage 1 OOMs |

Not a gotcha for this plan, but worth knowing: diffusers' H3 pipeline refuses durations under
4–5 s (V). expv2 uses DiffSynth's pipeline for inference, which only snaps to 17n+5.
